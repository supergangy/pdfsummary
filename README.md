# pdfsummary — 필기한 부분만 모아 주는 PDF 요약본

PDF 책에 **형광펜으로 칠한 부분, 밑줄 그은 부분, 동그라미 친 부분, 손으로 쓴 메모**만 뽑아서
단원별로 깔끔하게 정리해 줍니다. 손글씨는 Claude AI가 읽어서 글로 바꾸고, 애매한 글씨는 **원본 이미지를 같이** 넣어 줍니다.

```bash
pdfsummary 생명과학.pdf
```

```
📖 생명과학.pdf (3쪽) 에서 표시한 부분을 찾는 중…
  ✍️  손글씨 읽는 중 2/2
✅ 형광펜 5 · 밑줄 2 · 동그라미 1 · 손글씨 2 · 메모 2
   → 생명과학_요약/요약.html
   → 생명과학_요약/요약.md
```

| 결과물 | 쓰임 |
|---|---|
| `요약.html` | 브라우저로 바로 보기. 색·종류별로 걸러 보기 가능, **인쇄(Ctrl+P) → PDF로 저장**하면 요약본 PDF |
| `요약.md` + `images/` | 노션 · 옵시디언 · 깃허브에 붙여 넣기 |
| `요약.json` | 다른 프로그램에서 쓰기 (`--format json`) |

## 결과: 핵심 정리 요약집

Claude API 키가 있으면 기본 결과는 **주제별 핵심 정리 요약집**입니다. Claude가 책 쪽(스캔본이면 쪽 이미지)과 내 표시를 함께 읽고, 시험 공부 노트처럼 정리합니다.

```
Part 03 애플리케이션 › Section 07
SNMP 접근 제한 설정 핵심 정리
  한두 문장 개요 (핵심어 굵게)
  1. 개념 및 배경            목록
  2. 동작 원리 / 구조         🔐 소제목, 버전별 비교 표, 명령어 상자, 📌 꼭 외울 것, 📝 내 메모
  3. 예시 / 적용 시나리오      예상 문제 + 모범 답안
  4. 실무 및 시험 포인트 정리   주제 | 핵심 암기 내용 | 출제 빈도 ★★★ (책의 '23년.기사' 같은 기출 표시 기준)
```

- 내가 칠한 말은 요약집 안에서도 **형광펜으로** 보이고, 손글씨는 **📝 내 메모**로 관련 내용 옆에 붙습니다.
- 범위(`--scope`): **내가 표시한 주제 중심**(기본) 또는 **책 내용 전체**(표시는 강조). 표시가 하나도 없으면 전체로 정리합니다.
- 책 내용에 근거해서만 쓰도록 지시합니다. 예상 문제도 책 내용으로 답할 수 있는 것만.
- 비용: 쪽 이미지를 보내므로 쪽 수에 비례합니다 (실행할 때 예상 비용을 알려 줍니다, 대략 쪽당 1~2센트). 같은 책을 다시 만들면 캐시로 무료.
- 결과 HTML은 A4 인쇄용으로 맞춰져 있어 **인쇄 → PDF로 저장**하면 요약집 PDF가 됩니다.
- 무엇을 표시로 찾았는지는 함께 만들어지는 `표시모음.html`에서 확인할 수 있습니다.
- API 키가 없으면(또는 `--style list`) 예전처럼 표시한 부분 모음을 만듭니다.

## 내 컴퓨터 AI로 요약집 만들기 (Ollama, 무료)

Claude API 키가 없어도, 내 컴퓨터에서 AI 모델을 돌려 요약집을 만들 수 있습니다. 인터넷·비용이 들지 않는 대신 **느리고, 작은 모델일수록 정리 품질이 떨어집니다.** 어느 정도인지 직접 비교해 보는 용도로 넣었습니다.

1. [ollama.com](https://ollama.com)에서 Ollama를 설치하고 실행합니다.
2. 모델을 받습니다 (터미널). 컴퓨터 메모리에 맞춰 고르세요.

   ```bash
   ollama pull gemma3:12b     # 예: 쪽 이미지도 읽는 모델 (메모리 16GB 이상 권장)
   ollama pull gemma3:4b      # 예: 더 가볍지만 정리 품질은 낮음
   ```

   모델 이름은 Ollama 사이트의 목록에서 확인하세요. **그림(vision)을 읽는 모델**이면 스캔 쪽을 직접 보고, 글자만 다루는 모델이면 글자층·[글자 인식](#스캔본도-글자로-기기-안-글자-인식-무료) 결과로 정리합니다.
3. 실행 화면에서 **AI 엔진 → 내 컴퓨터 AI (Ollama)**를 고르고 모델을 선택합니다. 명령줄이라면:

   ```bash
   pdfsummary 책.pdf --ai ollama --model gemma3:12b
   ```

- 한 번에 2쪽씩, 하나씩 보냅니다 (요청마다 컴퓨터에 따라 몇 분). 결과는 저장해 두어 다시 만들면 바로 나옵니다.
- 그림을 못 읽는 모델에게는 손글씨 읽기를 맡기지 않습니다 (그림 없이 지어내기 때문에).
- 조절: `PDFSUMMARY_OLLAMA_CTX`(문맥 길이, 기본 16384), `PDFSUMMARY_OLLAMA_MAX_TOKENS`(답 길이, 기본 8192), `OLLAMA_HOST`(다른 컴퓨터의 Ollama).

## 가장 쉬운 방법: 실행 화면 (끌어다 놓기)

1. [Python 3.10 이상](https://www.python.org/downloads/)을 설치합니다. Windows는 설치 첫 화면에서 **"Add python.exe to PATH"를 체크**하세요.
2. 이 폴더에서 더블클릭합니다.
   - Windows: **`실행_Windows.bat`**
   - Mac: **`실행_Mac.command`** (처음에 "확인되지 않은 개발자" 경고가 뜨면 우클릭 → 열기)

   처음 한 번은 필요한 것을 설치하느라 1~2분 걸리고, 그다음부터는 바로 열립니다.
3. 브라우저에 화면이 열리면 필기한 PDF를 끌어다 놓습니다. 원본 PDF가 있으면 아래 칸에 같이 놓습니다.
4. 찾은 형광펜 색 중 **내가 칠한 색만 체크**하고, 원하면 색마다 의미(핵심, 정의 …)를 적습니다.
5. 정리 방법을 고르고 **요약 만들기** → 화면에서 바로 보고, HTML · Markdown(+이미지 zip) · JSON으로 저장합니다.

- API 키는 화면의 "API 키 넣기"에서 넣을 수 있고, "이 컴퓨터에 기억"을 켜면 다음부터 자동으로 씁니다 (`~/.pdfsummary/config.json`, 나만 읽을 수 있게 저장).
- 화면은 **내 컴퓨터 안에서만** 열립니다 (127.0.0.1). PDF는 임시 폴더에만 두었다가 창을 닫으면 지웁니다. AI를 켰을 때만 손글씨 이미지와 단원 본문이 Claude API로 보내집니다.
- 같은 책을 옵션만 바꿔 다시 만들면 AI 결과를 재사용해서 비용이 다시 들지 않습니다 (`~/.pdfsummary/cache/`).
- 명령어로 직접 열 수도 있습니다: `pdfsummary-app` (설치 후)

## 설치 앱 (Windows · Mac) — 파이썬 없이

파이썬 설치 없이 더블클릭으로 여는 앱입니다. 위의 실행 화면을 그대로 담았고, 창 아래 **끝내기**로 끕니다 (화면을 닫으면 3분 뒤 저절로 꺼짐).

- **받기**: GitHub 저장소 → Releases (v로 시작하는 태그를 올리면 자동으로 올라감), 또는 Actions → "설치 앱 만들기" 실행 결과의 Artifacts
  - Windows: `PdfSummary-Windows.zip` → 압축을 풀고 `PdfSummary.exe`
  - Mac (M1 이후): `PdfSummary-Mac.zip` → 풀고 `필기 요약.app`을 응용 프로그램 폴더로
- **처음 열 때 경고**: 서명하지 않은 앱이라 경고가 뜹니다.
  - Windows "PC 보호" 창 → **추가 정보 → 실행**
  - Mac "확인되지 않은 개발자" → 앱을 **우클릭 → 열기** (또는 시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기)
- 직접 만들기: `pip install . pyinstaller==6.22.3` 후 `cd desktop && pyinstaller --noconfirm pdfsummary.spec` (그 OS용만 만들어짐)

## 태블릿·폰 앱 (iOS · Android)

아이패드·갤럭시탭에서 PDF를 고르거나 굿노트·삼성노트에서 **공유 → 필기 요약**으로 보내 요약합니다. 앱은 `mobile/`에 있고, 만들고 스토어에 올리는 방법은 [mobile/README.md](mobile/README.md)에 있습니다.
PDF 분석은 기기에서 못 하므로 아래 **앱용 서버**가 하나 필요합니다.
API 키가 없으면 **기기 안 AI**(아이패드 Apple 기기 안 AI, 일부 갤럭시의 Gemini Nano)로 단원 개요와 표시마다 한 줄 설명을 무료로 붙일 수 있습니다 ([자세히](mobile/README.md#기기-안-ai-api-키-없이-무료)).

## 앱용 서버

```bash
pdfsummary-app --server --access-code "길고-아무도-모를-접속-코드"
```

또는 Docker로 (클라우드에 올릴 때):

```bash
docker build -t pdfsummary-server .
docker run -p 8080:8080 -e PDFSUMMARY_ACCESS_CODE="길고-아무도-모를-접속-코드" pdfsummary-server
```

| 환경 변수 | 뜻 |
|---|---|
| `PDFSUMMARY_ACCESS_CODE` | **필수**, 8자 이상. 앱 설정의 "접속 코드"에 같은 값을 넣음. 이 코드가 없으면 아무것도 못 함 |
| `ANTHROPIC_API_KEY` | 선택. 넣으면 접속 코드가 있는 **모든 사람의 AI 비용을 이 키로 냄**. 비우면 각자 앱 설정에 자기 키를 넣어 씀 (요청마다 보내고 서버에 저장 안 됨) |
| `PDFSUMMARY_TTL_MINUTES` | 올린 PDF·결과를 지우기까지 분 (기본 60) |
| `PDFSUMMARY_MAX_UPLOAD_MB` | 업로드 한도 (기본 300) |
| `PORT` | 받을 포트 (기본 8080, 클라우드가 정해 주면 그 값) |

- 아이폰·아이패드 앱은 **https** 주소만 붙을 수 있습니다. Render · Fly.io · Google Cloud Run 같은 곳에 Docker 이미지를 올리면 https 주소를 줍니다.
- 요약은 한 번에 하나씩 만듭니다 (여러 명이 동시에 쓰면 차례로 처리).
- 서버 상태 확인: `GET /healthz`

## 요약본은 이렇게 정리됩니다

형광펜 친 문장만 떼어 놓으면 문맥이 끊겨 무슨 말인지 모르기 쉬워서, 세 가지를 같이 붙입니다.

**1. 목차대로 정리** — 큰 제목 › 중간 제목 › 작은 제목 아래에 표시를 모으고, 맨 위에 목차(제목마다 표시 개수)를 붙입니다.
제목은 PDF 책갈피가 있으면 그것을, 없거나 부족하면 **본문보다 큰 글자·짧은 굵은 줄**을 찾아 씁니다. 매 쪽 반복되는 머리말·쪽 번호는 제목으로 보지 않습니다.
쪽별·색별로 볼 때(`--group-by page/color`)도 표시마다 `Ⅰ. 세포와 에너지 › 2. 세포 호흡 › 해당 과정`처럼 어느 단원인지 적어 줍니다.

**2. 앞뒤 문장 (AI 없이)** — 표시한 부분이 들어 있는 문장 전체를 보여 주고, 칠한 부분만 굵게 강조합니다.

> 해당 과정은 세포질에서 일어나며 **산소가 필요 없다**.

**3. AI 개요·연결 설명** — Claude가 단원 본문을 읽고
- 단원마다 **개요** (이 단원이 무엇을 다루고, 표시한 내용이 그 흐름에서 어디쯤인지),
- 표시마다 **연결 설명** (무엇에 대한 이야기인지, 앞 표시와 어떻게 이어지는지)을 1~2문장으로 붙입니다.

AI가 쓴 글에는 항상 **AI** 표시(Markdown은 💡)가 붙어 내가 칠한 원문과 섞이지 않습니다. 표시한 문장은 AI가 고쳐 쓰지 않고 원문 그대로 둡니다.
HTML에서는 위쪽 버튼으로 "앞뒤 문장", "AI 개요·설명"을 켜고 끌 수 있습니다.

| `--context` | 결과 |
|---|---|
| `auto` (기본) | AI를 쓸 수 있으면 `ai`, 아니면 `sentence` |
| `ai` | 앞뒤 문장 + AI 개요·연결 설명 |
| `sentence` | 앞뒤 문장만 |
| `none` | 표시한 부분만 |

AI 요청은 표시가 있는 단원마다 1번, 하위 단원이 여럿인 상위 단원마다 1번입니다(실행할 때 횟수를 알려 줍니다). 결과는 캐시에 저장되어 다시 실행하면 비용이 들지 않습니다.

## 무엇을 찾나

필기 앱마다 PDF에 필기를 저장하는 방식이 달라서, 세 가지를 모두 봅니다.

| 필기 방식 | 예 | 찾는 방법 |
|---|---|---|
| **PDF 주석**으로 저장 | Adobe Acrobat, macOS 미리보기, Xodo, Flexcil, PDF Expert 등 | 형광펜·밑줄·취소선 주석 아래의 글자를 정확히 읽음. 스티커 메모·텍스트 상자·형광펜에 단 댓글도 가져옴. 잉크(펜) 주석은 아래처럼 판정 |
| 필기가 **페이지에 굳어진** PDF | GoodNotes · Notability 등에서 "PDF로 내보내기" | 페이지 속 선 중 손으로 그은 획(반투명 굵은 획 = 형광펜, 둥근 끝 펜 획 = 펜)만 골라냄. 책의 표 선·도형은 건너뜀 |
| 종이책을 **스캔**한 PDF | 스캔 앱, 복합기 | 밝고 채도 높은 색(형광펜)을 찾아 그 부분을 잘라냄. 글자층(OCR)이 있으면 바로 읽고, 없으면 AI가 읽거나 이미지로 넣음 |

펜 획은 모양을 보고 나눕니다.

- **반투명하거나 굵은 획** → 형광펜 (밑에 있는 글자를 읽음)
- **글자 바로 밑의 납작한 선** → 밑줄 (위의 글자를 읽음)
- **글자를 감싸는 고리** → 동그라미 (안의 글자를 읽음)
- **그 밖의 획** → 손글씨 (원본을 잘라서 AI가 읽음. 별표·화살표 같은 기호는 "(별표)"처럼 표시)

그리고 정리할 때

- 줄이 바뀌며 이어 칠한 형광펜은 한 문장으로 합치고,
- 여백에 쓴 손글씨·메모는 **같은 높이(2줄 이내)의 형광펜·밑줄 밑에 붙여서** 무엇에 대한 메모인지 보이게 하고,
- PDF에 목차(책갈피)가 있으면 **단원별로**, 없으면 쪽별로 나눕니다.

## 책에 원래 있던 색칠과 내 형광펜 구분하기

교재 자체에 노란 강조나 빨간 밑줄이 인쇄되어 있으면, 필기본만 봐서는 내가 칠한 것과 헷갈릴 수 있습니다. 방법이 두 가지 있습니다.

### 1. 필기 전 원본 PDF와 비교 (가장 정확)

```bash
pdfsummary 필기본.pdf --original 원본.pdf
```

두 PDF를 쪽마다 겹쳐 보고 **필기본에만 있는 것**만 찾습니다. 책 자체의 색칠·밑줄·그림은 원본에도 똑같이 있으니 저절로 빠집니다.
화면에 보이는 차이를 보기 때문에, 필기 앱이 필기를 주석으로 저장하든 선으로 굳히든 **그림 한 장으로 덮어씌우든** 상관없이 찾습니다.
원본에는 글자층이 있고 필기본에는 없는 경우에도 원본의 글자를 씁니다.

- 쪽 번호가 같은 쪽끼리 비교합니다. 필기 앱에서 쪽을 추가했다면 `--pages`로 범위를 맞추세요.
- 쪽 모양이 크게 다르면(여백 추가 등) 그 쪽은 비교 없이 찾고 안내를 띄웁니다.

### 2. 내 형광펜 색만 인정 (원본이 없을 때)

먼저 이 PDF에서 어떤 형광펜 색이 나왔는지 봅니다.

```bash
pdfsummary 필기본.pdf --list-colors
```

```
색 코드          색        개수  쪽            예시
#F5E563       노랑       42  3,4,7,8,12…   활성화 에너지를
#FFF28C       노랑        9  2,5          기질 특이성
#FF8CBF       분홍       17  3,9,11       경쟁적 저해제
```

예시 글을 보고 내가 칠한 색의 코드를 골라 넣습니다. 같은 노랑이라도 코드가 다르면 구분됩니다.

```bash
pdfsummary 필기본.pdf --color "#F5E563" --color 분홍
```

- 색 코드(`#F5E563`)를 주면 그 색과 거의 같은 것만 받고, 색 이름(`분홍`)을 주면 분홍 계열 전체를 받습니다.
- 펜 색이 PDF에 그대로 들어 있는 경우(주석·선)에는 코드로 정확히 거르고, 종이 위 색만 보이는 경우(스캔·원본 비교)에는 색 이름 계열로 거릅니다.
- 밑줄·동그라미·손글씨는 거르지 않습니다.

### 스캔본도 글자로 (기기 안 글자 인식, 무료)

스캔한 책처럼 글자층이 없는 PDF는 **이 컴퓨터 안에서 글자를 인식(OCR)** 해서 읽습니다. 인터넷·AI·API 키가 필요 없습니다.
그래서 AI 없이도 스캔본에서 "칠한 문장 + 앞뒤 문장 + 목차 정리"가 그림이 아닌 **글자**로 나옵니다.

- 엔진: RapidOCR (PaddleOCR PP-OCRv5 한국어 모델, ONNX Runtime). 그래픽 카드 없이 돕니다 (쪽당 몇 초).
- **표시가 있는 스캔 쪽만** 인식합니다 (제목을 찾을 때는 그 앞 쪽까지). 인식한 결과는 저장해 두어 다시 만들면 바로 나옵니다 (`~/.pdfsummary/ocr_cache/`).
- 한국어 모델(약 13MB)은 설치 앱에는 들어 있고, `pip`으로 설치했다면 처음 쓸 때 한 번 받습니다. 미리 받으려면:

  ```bash
  python -m pdfsummary.ocr --download
  ```

- 끄려면 `--ocr off`. 요약집(AI)은 Claude가 쪽 이미지를 직접 읽으므로 새로 인식하지 않고, 이미 인식해 둔 글자만 곁들입니다.

### 문제집에 원래 인쇄된 색 글씨

스캔한 문제집의 청록색 강조 글씨, 하늘색 머리 띠, '23년.기사' 같은 기출 뱃지는 형광펜으로 잡지 않습니다.
형광펜은 글자 **뒤 바탕**을 칠하고(그 밑에 검은 글자가 있음), 인쇄된 색 글씨는 **글자 획만** 색이라는 차이로 구분합니다.
페이지 가장자리에 붙은 색 띠나 글자 없는 큰 색 상자도 장식으로 봅니다. 책이 바탕색으로 강조를 인쇄한 경우는 위의 원본 비교나 색 지정을 쓰세요.

## 삼성노트를 쓴다면

삼성노트에서 PDF로 내보낸 파일을 그대로 넣으면 됩니다. 필기가 어떤 형태로 저장되는지는 앱 버전에 따라 다를 수 있어서,
**원본 PDF를 함께 주는 방법(`--original`)을 권장**합니다. 이 방법은 저장 형태와 상관없이 동작합니다.

## 손글씨 처리 방식 (`--handwriting`)

| 값 | 결과 |
|---|---|
| `auto` (기본) | AI가 **확실히 읽은 것은 글로만**, 애매하거나(⚠ 표시와 애매한 부분 안내) 못 읽은 것은 **글 + 원본 이미지** |
| `ai` | 글로만 (AI가 못 읽은 것만 이미지) |
| `image` | AI를 쓰지 않고 원본 이미지 그대로 (`--no-ai`와 같음) |
| `both` | 항상 글 + 원본 이미지 |

AI에게는 손글씨 이미지와 함께 **주변 책 본문**을 같이 보내서, 흘려 쓴 전문 용어를 문맥으로 알아보게 합니다.
같은 이미지는 결과 폴더의 `.ai_cache.json`에 저장해 두므로 다시 실행해도 비용이 또 들지 않습니다.

Python 3.10 이상이 필요합니다.

### AI 설정 (손글씨를 글로 바꾸려면)

[Claude Console](https://platform.claude.com/)에서 API 키를 발급받아 환경 변수로 넣습니다. 키가 없으면 손글씨는 원본 이미지로 들어가고 나머지는 그대로 동작합니다.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

Windows PowerShell:

```powershell
$env:ANTHROPIC_API_KEY="sk-ant-..."
```

기본 모델은 `claude-opus-5-5`이고 `--model`로 바꿀 수 있습니다. 비용은 손글씨 덩어리 하나당 요청 1번입니다.

## 사용 예

```bash
# 기본: 단원별 정리, html + md
pdfsummary 책.pdf

# 색에 의미 붙이기 (형광펜 색을 구분해서 쓰는 경우)
pdfsummary 책.pdf --label 노랑=핵심 --label 분홍=정의 --label 파랑=예시

# 색별로 모아 보기 (예: 정의만 모아서 복습)
pdfsummary 책.pdf --group-by color --label 분홍=정의

# 일부 쪽만, 결과 폴더 지정
pdfsummary 책.pdf --pages 1-40,52 -o 1단원_요약

# AI 없이
pdfsummary 책.pdf --no-ai
```

| 옵션 | 설명 |
|---|---|
| `-o, --out 폴더` | 결과 폴더 (기본 `<파일이름>_요약`) |
| `--pages 1-30,45,50-` | 처리할 쪽 |
| `--original 원본.pdf` | 필기 전 원본과 비교해서 내가 더한 것만 찾기 |
| `--color 색` | 형광펜은 이 색만 (색 이름 또는 `#RRGGBB`, 여러 번/쉼표) |
| `--list-colors` | 찾은 형광펜 색 코드·개수·예시만 보여 주고 끝냄 |
| `--handwriting auto/ai/image/both` | 손글씨 처리 방식 (위 표) |
| `--no-ai` | AI 쓰지 않음 |
| `--model` | 손글씨를 읽을 Claude 모델 |
| `--group-by chapter/page/color` | 목차별(기본) / 쪽별 / 색별 |
| `--context auto/ai/sentence/none` | 문맥 보충 (위 표) |
| `--headings auto/toc/font` | 목차 찾기: 책갈피+글자 모양(기본) / 책갈피만 / 글자 모양만 |
| `--label 색=이름` | 색 의미. 색 이름은 노랑·주황·빨강·분홍·보라·파랑·초록 또는 yellow·orange·red·pink·purple·blue·green |
| `--no-attach` | 메모를 형광펜 밑에 붙이지 않고 따로 둠 |
| `--no-drawings` | 페이지에 굳어진 펜 획은 찾지 않음 (책 속 그림이 손글씨로 잘못 잡힐 때) |
| `--scan auto/on/off` | 스캔 이미지에서 형광펜 색 찾기 (기본: 스캔 페이지에서만) |
| `--ocr auto/off` | 스캔 쪽 글자 인식 (기본: 표시가 있는 스캔 쪽만) |
| `--ai auto/claude/ollama` | AI 엔진 (기본: Claude 키가 있으면 Claude) |
| `--ollama-host` | Ollama 주소 (기본 `http://127.0.0.1:11434`) |
| `--format html,md,json` | 만들 파일 |
| `--title` | 요약본 제목 |
| `--dpi` | 원본 이미지 해상도 (기본 200) |

## 한계

- **스캔본의 검정 펜 손글씨**는 인쇄 글자와 색이 같아서 찾지 못합니다. 스캔본에서는 색 있는 형광펜만 찾습니다. (원본 PDF가 있으면 `--original`로 찾을 수 있습니다)
- 원본 없이 쓰면, 책 자체의 **반투명한** 색 강조는 내 형광펜과 구분되지 않을 수 있습니다 → `--original` 또는 `--color`.
- 책 자체에 손그림 같은 곡선 그림이 많으면 손글씨로 잘못 잡힐 수 있습니다 → `--no-drawings`.
- 밑줄·동그라미 판정은 모양을 보고 추정하는 것이라 가끔 손글씨로 분류될 수 있습니다 (그래도 원본 이미지가 남습니다).
- 글자 모양으로 찾는 제목은 책 디자인에 따라 빠지거나 본문 강조 줄이 제목으로 잡힐 수 있습니다 → `--headings toc`.
- 두 단으로 된 책은 읽기 순서·단원 경계가 어긋날 수 있습니다.
